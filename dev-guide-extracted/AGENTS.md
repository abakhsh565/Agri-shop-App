# Agri Shop Management System (AgriShop) — Engineering Instructions

React + Vite + Tailwind CSS project running inside Figma Make. This file merges
the runtime environment facts with the project's engineering governance. The
repository — not chat history — is the source of truth (ADR-003).

## Delivery Decision (ADR-006)
AgriShop ships as an installable **Progressive Web App (PWA)** built with
React 19 + Vite + Tailwind CSS v4, backed by **Supabase** (PostgreSQL + Auth +
Realtime). This supersedes the earlier Flutter (ADR-001) and NestJS (ADR-002)
baselines. Goals: runs on Android and iPhone from one codebase, real-time data
sync across devices, and support for future inventory automation/integrations.

- `src/App.tsx` — root component; applies theme and renders the router.
- `src/router/` — route definitions (admin + employee).
- `src/pages/` — screen components (admin/ and employee/ trees).
- `src/components/`, `src/stores/` (Zustand), `src/lib/` — UI, state, and data/logic.

- `public/manifest.json`, `public/sw.js` — PWA manifest and service worker.
- `supabase/functions/server/` — Figma Make edge-function server (autogenerated pieces; do not edit `kv_store.tsx`).
- `utils/supabase/info.tsx` — autogenerated Supabase project id + anon key (do not edit).

## Styling
Tailwind CSS v4 via the `@tailwindcss/vite` plugin (configured in
`vite.config.ts`). `src/index.css` imports Tailwind with `@import 'tailwindcss';`.
Use Tailwind utility classes in JSX; put global CSS or Tailwind v4 theme
customization in `src/index.css`. No Tailwind config or PostCSS config needed.
Global font wiring belongs in `src/index.css` — keep `@import` statements first,
then `@font-face` rules and font-family defaults.

## Non-Negotiable Rules
- Never expose secrets, service-role keys, or database credentials in the client. The browser uses only the anon key with RLS.
- Never trust client-supplied role, price, cost, balance, profit, stock, or permission values. Server/database rules are authoritative.
- Enforce authorization in the database (RLS + column grants), not only by hiding UI.
- Employees must never receive supplier financials, purchase/base cost, or gross profit.
- Never allow inventory to become negative.
- Never hard-delete completed financial, sales, purchase, payment, return, or inventory records; correct via reversal/return/adjustment (ADR-004).
- Never retroactively change the selling price stored on a historical sale.
- Inventory adjustments and returns require an auditable record; returns must originate from an eligible original sale.
- Database schema changes are applied as versioned SQL. Do not rewrite architecture without a new ADR.

3. Inspect existing code/tests before changing anything.

## Change Management
Iterative UX / content / IA / data / screen changes are managed through the **Change Registry**
in `changes/` — the single source of truth for changes on top of CHANGELOG/ADR/ROADMAP:
- `changes/README.md` — control panel: the index of all changes + the lifecycle
  (Draft → Proposed → Approved → In Progress → Implemented → Verified → Done).
- `changes/IMPACT_MAP.md` — dependency backbone (routes ↔ flows ↔ stores ↔ entities ↔ i18n);
  every change points at these anchors so cross-app impact is understood and screens/flows/
  content/data stay synchronized.
- `changes/_TEMPLATE.md` — copy to `CR-00N-<slug>.md` per change.

Workflow: capture a CR → analyze & fill its Impact Map/dependencies against `IMPACT_MAP.md` →
get user approval → implement **one approved CR at a time**, updating every impacted screen,
flow, content key, and data path together → verify (`tsc` + `build` when code changes) → mark
Done + append `CHANGELOG.md` (spawn an ADR if architectural). Keep `IMPACT_MAP.md` current when
structure changes.
